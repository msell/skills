# Repair an existing skill

1. Accept a skill directory, `SKILL.md` path, or installed name. For a name, look in the user's configured skill roots and the current project's provider roots. Resolve symlinks and distinguish multiple installed copies. Ask which copy to repair only if the request and source ownership do not identify one.
2. Read the existing `SKILL.md`, metadata, and the scripts and references its workflow uses. Record the current invocation policy, resource paths, and source location before making focused edits. Preserve the existing workflow; do not regenerate it from the creation template.
3. Edit the canonical source. For a repository-managed skill, follow the links to its checkout and follow that checkout's instructions even when the current working directory is elsewhere. For a standalone skill already under `~/.agents/skills`, edit it in place. Avoid creating a second copy merely because the current directory is a skills checkout.
4. For an unmanaged standalone skill stored only in another provider's user directory, move the complete directory into `~/.agents/skills/<name>/` if that destination is vacant, then replace its old entry with a symlink so that provider still discovers it. For Claude, use the relative link specified in `SKILL.md`. Verify the moved contents before linking. If the destination already contains another copy, report the conflict instead of merging or overwriting it.
5. Treat plugin caches and package-managed installs as managed sources. Find their editable source checkout, or create a user-owned copy with all resources and licenses when the user requested a local adaptation. Keep the managed original intact and check provider precedence for duplicate names before claiming the adaptation is active. Preserve project scope for project-local skills.
6. Ensure the target providers can discover the repaired source. For standalone user skills, create the Claude link using the relative target in `SKILL.md` when it is missing; normalize an existing link to that relative target only if it already resolves to the same source. If another installation occupies a required path, report it rather than replacing it. Use a checkout's installer for repository-managed links.
7. Return to the common formatting, portability, and verification sections in `SKILL.md`. Repairing an existing skill is authorized by the repair request; an occupied path is not itself a reason to refuse the task.
